# مرجع معمارية منصة Soulove SaaS وعزل المستأجرين (Tenant Isolation & System Architecture)

هذا المستند مرجع دائم وإلزامي للنظام قبل أي تعديل أو تطوير على المشروع.

---

## 1. فكرة المشروع

المنصة عبارة عن **Multi-Tenant SaaS** مخصصة لإنشاء مواقع رومانسية شخصية معزولة بالكامل.
كل عميل يحصل على:
- موقع خاص به على رابط مستقل (مثال: `soulove.com/ahmed-sara`).
- لوحة تحكم (Dashboard) خاصة به.
- كلمة مرور لفتح الموقع وكلمة مرور للوحة التحكم.
- بيانات وملفات مستقلة تماماً عن أي عميل آخر.

---

## 2. نظام المستخدمين والصلاحيات

1. **Super Admin**:
   - مالك المنصة.
   - يستطيع إنشاء، حذف، تفعيل، أو تعطيل المواقع، وتعديل بيانات العملاء وإدارة كلمات المرور والمحتوى بالكامل.
2. **العميل (Client)**:
   - يمتلك Dashboard وصور وأغاني وذكريات وإعدادات خاصة به لا يراها غيره.
3. **الزائر (Visitor)**:
   - يدخل كلمة المرور الخاصة بالموقع لمشاهدة المحتوى فقط.

---

## 3. العزل التام بين العملاء (Tenant Isolation - القاعدة الأهم)

- كل عملية (قراءة، تعديل، حذف، رفع ملفات، تحميل، تسجيل دخول) **يجب أن تكون مرتبطة دائماً بـ `slug` الموقع**.
- جميع استعلامات قاعدة البيانات يجب أن تستخدم صراحة: `WHERE slug = $1`.
- **يُمنع منعاً باتاً**:
  - جلب أو تعديل بيانات أكثر من عميل في نفس الطلب.
  - مشاركة الملفات أو الجلسات أو الكاش (`localStorage` / `sessionStorage`) بين العملاء.

---

## 4. إنشاء موقع جديد

عند إنشاء عميل جديد من Super Admin:
- إنشاء سجل جديد في PostgreSQL وتوليد بيانات افتراضية أولية مرّة واحدة فقط.
- إنشاء مجلد ملفات مستقل للعميل على خادم الميديا:
  `/var/www/uploads/:slug/` (يحتوي على: `gallery/`, `music/`, `memories/`, `avatars/`).

---

## 5. البيانات الافتراضية (Seed Data)

- البيانات الافتراضية تُستخدم **مرة واحدة فقط** عند إنشاء الموقع لأول مرة.
- بعد الحفظ الأول، تصبح قاعدة البيانات PostgreSQL هي المصدر الوحيد للحقيقة (**Source of Truth**).
- يُمنع منعاً باتاً إعادة حقن البيانات الافتراضية أو استبدال بيانات العميل.

---

## 6. قاعدة البيانات والتخزين

- التخزين الرئيسي في **PostgreSQL**.
- **لا يُسمح بتخزين الصور أو الأغاني كـ Base64 نهائياً** داخل الداتابيز أو داخل كائنات الـ JSON.
- يتم تخزين الروابط المباشرة القابلة للوصول فقط:
  ```json
  {
    "image": "https://media.soulove.app/uploads/ahmed/photo.webp",
    "audio": "https://media.soulove.app/uploads/ahmed/song.mp3"
  }
  ```

---

## 7. الملفات والوسائط (Media Storage)

- الصور والأغاني لا تمر عبر طلبات Vercel.
- تُرفع وتتخزن مباشرة في مجلدات الـ VPS المخصصة لكل عميل (`/var/www/uploads/:slug/`).

---

## 8. نظام الحفظ (Save System)

- عند الحفظ، يُرسل فقط كائن JSON خفيف يحتوي على النصوص والروابط القابلة للوصول.
- حجم طلب الحفظ يجب أن يظل صغيراً جداً (**أقل من 10KB**) لكل عملية حفظ لضمان أسرع استجابة وتفادي قيود الحجم.

---

## 9. الأداء والتوسع (Performance & Scalability)

- النظام يجب أن يدعم آلاف العملاء والمواقع والملفات بدون بطء، أو أخطاء، أو تجاوز حدود Vercel.

---

## 10. الأمان والمصادقة (Authentication & Tokens)

- حماية كافة مسارات الدخول والرفع والتعديل والحذف باستخدام توكنات جلسة **JWT (JWT Session Tokens)** لتجنب إرسال كلمة المرور مع كل طلب.

---

## 11. سياسة الرفع والتحديث على Git (Strict Git Push Policy)

- **يُمنع منعاً باتاً رفع أو عمل `git commit` أو `git push` للمشروع إلى GitHub/Git إلا بعد الحصول على إذن صريح وطلب مباشر ومكتوب من المستخدم.**

---

## 12. الهدف النهائي

إنشاء منصة SaaS مستقرة، سريعة، معزولة بالكامل، قابلة للتوسع لآلاف العملاء بدون فقدان بيانات أو مشاكل أداء.
